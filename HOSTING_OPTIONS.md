# Inexpensive hosting for this portfolio

Prices checked against official sources on **6 September 2026**. Amounts are monthly USD unless marked EUR; taxes, domain registration, optional services, and usage beyond included allowances can add to the bill. Provider currency prices are shown directly because your card's INR exchange rate and fees vary.

This is one Next.js application: its frontend and backend routes (`/api/health` and `/api/contact`) can run together on one host. The standalone Docker image runs a Node server on port 3000. The contact form saves messages to a JSONL file, so it needs a persistent volume. There is no need to buy separate frontend hosting, a second backend server, or a database when using a Docker host with durable storage.

For the lowest bill and least setup, choose **Vercel Hobby** if the portfolio meets its personal, noncommercial rule and you use a mailto contact link or adapt contact storage. For a free deployment of the existing Docker app, choose **Render Free** and accept the cold-start delay, using mailto instead of persistent file submissions. For a straightforward paid Docker deployment, **Render Starter at $7/month plus disk storage** is easier to budget than usage-based hosting; **Railway starts at $5/month** and may cost more depending on consumption. These are recommendations based on the current app's simple requirements, not measured load-test estimates.

If you want to administer a server, compare **Hetzner's €5.99 including IPv4 before VAT** with **DigitalOcean's $6 1 GiB plan**. Hetzner gives more memory at that price; DigitalOcean offers an India region. A VPS can host both frontend and backend in the existing single container, with an HTTPS reverse proxy in front of port 3000.

For durable contact submissions, mount the app's configured data directory on a Railway volume, Render paid persistent disk, or VPS Docker volume. Railway persistent **volume** usage costs **$0.15/GB-month** (object buckets are a different product at $0.015/GB-month); Render persistent disk storage costs **$0.25/GB-month** (for example, $7 Starter + a 1 GB disk = **$7.25/month on a $0 Hobby workspace** before other charges). These are storage charges in addition to the compute model described above; Railway's included credit applies to resource usage. Keep backups of received messages. [Railway resource rates](https://docs.railway.com/pricing), [Railway bucket rates](https://docs.railway.com/storage-buckets/billing), [Render storage pricing](https://render.com/articles/how-much-does-cloud-application-hosting-cost-for-small-businesses), [Render persistent disks](https://render.com/docs/disks).

A static frontend host only serves generated files. Converting the app to a static export would require removing or separately hosting any dynamic server behavior; `/api/health` would no longer verify a live Node process. Keep the full Next.js runtime if you want backend routes. Use `/api/health` as the deployment health-check path and configure the server to listen on the host's assigned port and `0.0.0.0` where required. No cloud service has been purchased or deployed as part of this comparison.

## Hosting the portfolio and the upgraded projects together

The Android app runs on the phone; distributing its debug APK through a GitHub prerelease does not require an always-running backend. The local PhishScope workflow does not call an LLM, so its demo has no model API bill. Image Trust Desk verifies local attestations and likewise has no third-party API cost. BITS Social needs its API, PostgreSQL, Redis and persistent media/demo data; it has more moving parts than the portfolio.

Render’s Hobby workspace includes 5 GB outbound bandwidth and 500 standard build minutes per month; overages cost $0.15/GB and $5/1,000 build minutes. The optional Pro workspace fee is not needed for the Starter examples above. [Render billing and allowances](https://render.com/articles/how-much-does-cloud-application-hosting-cost-for-small-businesses).

**My low-cost recommendation:** publish the portfolio free first and link screenshots, source branches and APK/releases. If you want the interactive demos publicly accessible all the time, put the Docker apps on one small VPS, isolate the databases from the public network, and use separate subdomains through Caddy or another HTTPS proxy. Keep the demo identity and review controls isolated from real users. The local verifier has no authentication and must be protected before public exposure.

Before cloud deployment, replace `http://localhost:3101`, `:3102`, and `:3104` demo links with the real HTTPS addresses. Local demo URLs only work on the machine where these containers run. The source lives on named feature branches, so select the specific branch from `PROJECT_RELEASES.md` in your host's build settings rather than the older default branch.
